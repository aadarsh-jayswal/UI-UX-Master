# New product interface

Use only for a multi-stage creation task. These are conditional stages, not a fixed interview or mandatory seven-skill chain.

1. Establish the primary task, audience facts actually known, platform, scope, and completion condition. Router or interface owner keeps the compact handoff record.
2. Use user-research only if unanswered behavioral questions block a sound decision or the user requested research. Otherwise label assumptions and proceed with reversible design choices.
3. ui-design-toolkit owns the creative direction, visual narrative, flow/state map, and concrete interface. Develop distinctive imagery, typography, composition, and interaction alongside usability. Use [taxonomy](../references/page-taxonomy.md) when it helps classification. Copy and handoff are modes of the same owner.
4. Use design-system only for a shared contract or requested DESIGN.md; do not create a complete token hierarchy for a one-off component.
5. Proactively use animate for substantial choreography, visual storytelling, or expressive interaction that strengthens the design; no separate animation request is needed. Use fixing-accessibility for a requested audit or specialized defect. The interface owner still implements ordinary interaction polish and accessible semantics.
6. Optional provider output is input to the interface owner, not permission to change platform or publish. Check integration access before dependent work.
7. Verify visual impact, narrative, hover/focus/touch behavior, motion, the requested path, and affected alternative states/viewports as relevant to the brief. Hand off exact artifacts and remaining checks. One artifact has one writer at a time.

Direct focused tasks may skip this playbook entirely. No automatic research, variant picker, material style, media generation, external action, or agent delegation.
