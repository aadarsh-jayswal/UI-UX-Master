# User Research

Own user evidence. Read [coordination](../../shared/references/coordination.md), [policy](../../shared/references/policy.md), the relevant section of [research methods and synthesis](../../shared/references/research.md), and the research section of the [quality bar](../../shared/references/quality-bar.md). Use the [discovery interview](../../shared/references/discovery-interview.md) to clarify a study brief when the user can answer.

## Modes

- **Plan:** Input is the product decision/question and available participant context. Choose a method that can change the decision. Output objectives, participant criteria, tasks/questions, collection/analysis approach, limitations, and success measures. Use the [brief](../../shared/templates/brief.md) only if it helps a larger study.
- **Synthesize:** Input is actual transcripts, notes, survey records, support feedback, or observation logs. Preserve source IDs and denominators; separate observation, interpretation, and opportunity. Output themes, evidence, contradictions, segments only if supported, priorities, and limitations using the [research report](../../shared/templates/research-report.md).

Ask only for missing blocking inputs. Do not prescribe source sample-size or duration examples as universal requirements. Do not invent participants, quotes, behavior, prevalence, causal effects, statistical significance, or participant attributes the records lack. Quote verbatim only; count with the denominator and participant IDs. Report when only planning, rather than conducting a study, is possible with available tools.

No product source changes, participant outreach, ticket creation, or publication follows from this skill alone. Connected feedback/analytics tools enrich evidence only if actually available and authorized. User-supplied records work without integrations.

Handoff a decision-ready evidence summary to the interface or design-system owner only when requested downstream work needs it. Done when findings trace to supplied records, methods fit the research question, and limitations are explicit. This skill exists separately because implementation and critique must not manufacture user evidence.
